title: 大模型是怎么训练出来的？
---

你在用 Opus 5.5、DeepSeek 的时候，是不是也好奇过，这个大模型到底是怎么训练出来的？

![](https://cdn.paicoding.com/stutymore/how-llm-is-trained-agent-workflow-20261117222156-e7d89815.png)

你输入提示词，Opus 5.5 会先输出一段思考过程，把任务拆分成几个步骤，接着调用工具读文件、查资料、跑命令，遇到报错还能自己修好。但模型刚搭建好的时候，内部的参数全是随机生成的数字，连一句通顺的话都说不出来。要把这样一个模型训练成能写教程，能做视频的 Opus 5.5，需要经过四个阶段：预训练、中训练、SFT 监督微调和 RL 强化学习。前两步决定模型储备了多少知识，后两步决定它能不能听懂指令、把任务做对。

**那聪明的你一定会问，预训练是怎么把海量知识装进模型参数里的？**

预训练阶段用的是自监督学习，基于互联网上海量的文本和代码，让模型根据前文预测下一个 Token。Token 是模型处理文本的最小单位，可以是一个字、一个词，也可以是词的一部分。

之所以不需要人工标注，是因为原文本身就是标准答案，下一个词是什么，原文里写得清清楚楚。训练效率之所以高，靠的是 Transformer 的 Decoder-only 架构和因果掩码。

训练时，把一整段文本一次性送进显卡，然后用因果掩码把每个位置后面的内容遮住。只要做一次前向计算，模型就能同时完成每个位置的预测，根据第 1 个 Token 预测第 2 个，根据前 2 个 Token 预测第 3 个，以此类推。除了最后一个 Token，每个位置都能算出模型的预测和真实原文之间的误差，再通过反向传播调整参数。十几万亿到几十万亿个 Token 训练下来，语法规律、生活常识和代码逻辑就都被记进了参数里。

但预训练有两个局限。第一是成本高，算力和数据清洗占了整个训练预算的大头，而且原始语料里如果混进了错误的内容，模型也会跟着出错。第二是预训练出来的基座模型只会顺着上文往下续写。这时候你问“王二讲 Agent 开源了吗？”，基座模型通常不会回答你，而是顺着这句话接着往下续写。

**那聪明的你肯定会继续问，预训练完了为什么不马上做微调，还要加一步中训练？**

早期的训练流程确实是预训练完就进微调，但现在的旗舰模型普遍在中间加了一步中训练，也就是 Mid-training。中训练的目标没变，还是对整段文本的每个 Token 预测下一个 Token，但训练数据的配比和文本长度变了。

它主要解决两件事。第一件是拉长上下文窗口。在标准的注意力机制里，文本长度翻一倍，注意力部分的计算量大约要翻四倍。如果从预训练第一天起就全程用百万 Token 长度的文本去训练，算力开销太大。工程上的做法是，先在短文本上完成大部分预训练，到了中训练阶段，再把文本长度拉长，直到撑起像 Opus 5.5 这样的 1M 上下文窗口。第二件是补充高质量的专业语料，比如完整的开源代码库、完整的数学推导和多轮工具调用记录，重点加强模型的工程和推理能力。

中训练的难点在于控制遗忘。如果这一步全喂代码和数学题，模型很容易忘掉预训练阶段学到的日常知识。所以中训练必须按一定比例混入通用语料，保住原有的知识。反过来，如果模型本身缺乏某类专业知识，又跳过中训练，只拿少量数据去做微调，模型只会死记硬背，换个问法照样不会。

**聪明的你可能会继续问，SFT 监督微调做了什么，它和预训练有什么区别？**

经过前两步，模型储备了知识，也能读长文档了，但它还不知道怎么跟你交流，也不知道怎么调用工具。SFT 监督微调，就是拿大量高质量的示范数据，教模型按规矩回答问题和调用工具。

在底层计算上，SFT 和预训练一样，也是预测下一个 Token。两者的核心区别是，预训练是对整段文本的每一个 Token 都算误差；而 SFT 会把用户输入的提示词，以及工具执行后返回的结果遮住，只对模型自己输出的思考过程和工具调用计算误差、更新参数。这样模型就学会了，收到任务后该怎么做出回应、怎么执行命令。

SFT 的优点是见效快，用相对少量的数据就能把回答格式和工具协议固定下来。但它的上限也被示范数据锁死了。因为示范都是正确路径，模型只是在模仿现成答案。一旦遇到示范数据里没见过的报错，模型就很难自己找到解决办法。

**最后聪明的你还会问，既然 SFT 已经立好了规矩，为什么还要花大力气做强化学习？**

因为 SFT 教的是怎么正确回答一个问题，而 RL 强化学习练的是在真实环境里怎么把事情搞定。早期的强化学习主要是 RLHF，也就是基于人类反馈的强化学习，让标注员比较模型的两个回答哪个更好，先训练一个负责打分的奖励模型，再用 PPO 算法更新模型参数；后来又出现了 DPO，直接拿好的回答和差的回答做对比训练，省掉了额外训练奖励模型的开销。

到了 Opus 5.5 这类顶级模型，训练重心转向了有客观检验标准的强化学习，常用 GRPO 这类强化学习算法。针对同一个任务，让模型一次生成十几条不同的操作轨迹，也就是从接到任务到交出结果的完整操作过程，再放进隔离的沙箱环境里跑测试。测试通过给正分，报错或者输出格式解析失败记 0 分，再拿这一组轨迹的平均分当基准，高于平均分的轨迹提高生成概率，低于平均分的降低生成概率。经过成千上万次的试错，模型不仅学会了长程任务的解法，还练出了先在思考过程里规划方案、看到报错就主动修改的能力。

不过强化学习也有门槛。第一，它要反复生成和测试大量轨迹，算力开销比 SFT 高得多，而且只能强化模型原本就有一定概率做对的能力。如果一道题模型连续几十次全是 0 分，整组轨迹没有分差，参数就找不到更新方向。第二，只看最终测试通没通过，模型容易钻空子，比如去修改报错的测试用例，或者活还没干完就提前收工。所以训练时要用模型改不了的隐藏测试，并对违规动作扣分。到了实际使用阶段，Claude Code 这类 Harness 还提供了 Stop 钩子，在模型准备结束时触发检查，一旦发现 Opus 5.5 还没按要求交出结果就想提前收工，就会拦住它，追加提示词让它继续干活。

最后简单总结一下。训练一个像 Opus 5.5 这样的顶级大模型，需要四步。预训练在海量文本上预测下一个 Token，把通用知识装进参数。中训练把上下文窗口拉长到百万级，再补齐代码和推理方面的专业知识。SFT 只对模型自己的输出算误差，教会它对话格式和工具调用规则。强化学习再把它放进沙箱里反复试错，练出深度思考和多步解决问题的能力。
